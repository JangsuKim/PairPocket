# 2026-09-20 실행 기준선 및 코드 검수

## 검증 환경

- Xcode 27.0 (27A266a).
- iPhone 17 Simulator, iOS 26.3.1.
- 앱/테스트 최소 버전 iOS 17.0, 기기 대상 iPhone으로 통일.
- 전체 단위 테스트: 58개 테스트, 파라미터별 실행 포함 60건 통과.
- Release iOS 기기용 빌드: 서명 없이 성공. 실기기 설치 검증은 별도 필요.
- `git diff --check` 통과. SwiftLint 실행 파일은 설치되어 있지 않아 실행하지 않음.
- iOS 17 런타임 실행 및 화면 전체 수동 조작은 이번 검증에 포함하지 않음.

## 수정한 문제

1. 카테고리 아래 방향 이동: 원래 배열 기준 drop 위치에서 먼저 제거한 항목 수를 차감하지 않아 한 칸 더 이동했다. 위/아래/다중 선택 회귀 테스트 추가.
2. 정산 이후 공동잔액: 미정산 항목만 계산하는 정산 요약을 잔액 표시에도 사용했다. 전체 유효 거래를 계산하는 `currentPocketBalance`를 추가하고 홈·포켓 목록·상세에 적용.
3. 삭제 거래: 도메인 정산 계산에서 삭제 플래그와 타임스탬프를 모두 제외. 정산 실행에서도 삭제 거래와 입금을 제외.
4. 삭제 상태 저장: `ExpenseRecord.isDeleted`는 SwiftData 자체 삭제 상태와 이름이 겹치며 테스트에서 저장 후 false가 되는 것을 확인했다. 기존 스키마를 유지하면서 `deletedAt`을 영속 소프트 삭제 기준으로 사용하고, 도메인 플래그만 전달된 입력에도 타임스탬프를 설정한다. 도메인으로 복원할 때 플래그는 타임스탬프에서 계산한다.
5. 기존 지출 편집: 포켓 비율 변경 후 메모만 수정해도 기존 지출 비율이 바뀌었다. 같은 포켓 내 편집에서는 거래에 저장된 비율을 표시·보존한다. 다른 포켓으로 옮기는 경우 새 포켓의 비율을 적용한다.
6. 정산 저장 실패: 홈과 정산 탭에서 `try?`로 버리던 오류를 표시하고 실패 시 컨텍스트를 rollback한다.
7. 테스트 격리 경고: identity 테스트를 MainActor에서 실행해 모델 Equatable 격리 경고를 해소.

## 정리한 코드

- 호출되지 않는 PocketStore의 단순 addPocket overload와 setMainPocket.
- 호출되지 않는 CategoryStore.deleteCategory와 ExpenseStore의 비어 있는 identity backfill.
- 빈 예제 테스트. 실제 SwiftData 저장소 회귀 테스트로 대체.
- 카테고리 시트의 중복 editMode 설정.
- 홈 정산 영역의 중복 엔화 포매터. YenFormatter로 통합.
- 공유 scheme에 항상 켜져 있던 SQL 디버그 로그.

삭제한 코드는 Git 기준 버전에서 복구할 수 있다. 관계/사용자 ID 모델 등 향후 연동에 필요한 모델은 유지했다.

## 남은 검토 사항

### 우선 보완

- 금액 상한과 도메인 검증: 금액 입력이 Int 범위 내여도 `amount * ratio` 또는 합산에서 overflow가 가능하다. 입력 상한, 비율 합계 100 검증, 정산 합산 한계를 함께 정해야 한다. 정상 금액 테스트 통과가 임의의 큰 값에 대한 안전성을 의미하지 않는다.
- iCloud 설정 화면: 시작 버튼은 UserDefaults 값만 바꾸고 초대 버튼은 비어 있다. 실제 연동 없이 동기화가 시작됐다고 표시될 수 있다. 구현 전에는 준비 중 표시와 버튼 비활성화가 필요하다.
- 초기 로드 오류: 여러 화면의 `try?`가 저장소 읽기 실패를 빈 목록처럼 보이게 할 수 있다. 공통 오류 표시 및 재시도 경로가 필요하다.

### 정책 및 후속 구현

- 정산액 0원인 미정산 거래는 현재 완료 처리할 수 없다. 상쇄된 거래도 마감할 수 있게 할지 결정 필요.
- 전체 정산은 모든 포켓을 한 번에 반올림한다. README의 포켓별 정산 원칙과 일치하도록 포켓별 반올림 후 합산할지 결정 필요.
- 입금은 생성만 지원하고 상세 화면에서 수정·삭제할 수 없다. README의 expense/deposit CRUD 완료 표기는 실제 범위보다 넓다.
- 기존 지출의 비활성 카테고리는 편집 화면에서 활성 카테고리로 대체될 수 있다. 비활성 기존 선택의 보존 정책 필요.
- ExpenseRecord는 createdAt을 따로 저장하지 않고 거래 날짜로 복원한다. 정확한 생성일 보존에는 스키마/마이그레이션 작업이 필요하다.
- 실기기의 `.automatic` 설정만으로 CloudKit 동기화 활성화 또는 강제를 단정할 수 없다. entitlement와 컨테이너 설정, 실제 기기 동작을 함께 확인해야 한다. 이번 작업에서 동기화 설정이나 저장 스키마는 변경하지 않았다.
- 최소 지원 버전 17.0은 빌드 설정이며 실제 iOS 17 실행 보증은 아니다. 해당 런타임/기기에서 별도 검증 필요.

## 재현 명령

설치된 시뮬레이터 ID는 `xcrun simctl list devices available`로 확인한다.

```sh
xcodebuild test -project PairPocket.xcodeproj -scheme PairPocket \
  -destination 'platform=iOS Simulator,id=<SIMULATOR_ID>' \
  -parallel-testing-enabled NO -collect-test-diagnostics never \
  CODE_SIGNING_ALLOWED=NO

xcodebuild build -project PairPocket.xcodeproj -scheme PairPocket \
  -configuration Release -destination 'generic/platform=iOS' \
  CODE_SIGNING_ALLOWED=NO
```

실패 테스트의 진단 수집이 오래 걸려 재현 실행 두 건은 실패 로그 확인 후 중단했다. 최종 전체 테스트는 정상 종료(exit 0)했다.
